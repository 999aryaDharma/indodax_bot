# Architecture decisions

ADR required for process boundaries, source-of-truth, major dependencies, data identity, security, public interfaces, persistence, deployment topology or accepted major residual risk. Ordinary implementation naming/refactors do not need ADR.

Statuses: PROPOSED → ACCEPTED → SUPERSEDED (with replacement ID), or REJECTED. Planning decisions below codify existing scope or resolve explicitly identified specification inconsistencies; they do not assert runtime already implements them. A material scope expansion still needs owner approval.
